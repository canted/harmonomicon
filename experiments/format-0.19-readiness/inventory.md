# Concrete pre-1 supported profile and remaining decisions

**Review baseline:** candidate 0.19 at `eab8745`. Independent recheck confirms the three identified PNG defects are closed; no focused concrete finding remained. This review neither defines nor declares 1.0. In-app authoring/composition remains primary; portability is a secondary potential benefit with uncertain demand.

The bounded ordered-runbook core is reusable across several families. Four new cross-family arrangements pass both engines, schema, restart at every event boundary and actual durable hosts. Six negative witnesses and the image-read workaround establish important limits. These are a small constructed challenge, not a representative or blind coverage estimate.

Audio/video, dynamic calendars, image routing, streams and permission enforcement are **unsupported capabilities**, not merely UI chores; their necessity depends on the supported scope. Upload processing/drafts/notifications/chat/boards are host integration, not automatic language gaps.

## Host integration contract

The host imports an immutable `(id, version)` definition, negotiates its exact format/required operation/policy/capability tokens and rejects unsupported setup before state creation. It binds a fixed participant roster, a distinct organizer, saved settings and any trusted random seed. It authenticates the actor, supplies a monotonic integer clock, serializes accepted events and effects atomically, persists the ledger/state and runs deadline progression without participant reads. Accepted event-ID retries replay the frozen identity; changed reuse rejects. Client transport cannot claim actor, time, seed or media authority. Historical private projections must survive restart and later phases.

For image values the runtime checks exact `{ref}` shape and a nonempty scalar reference of at most 256 code points. An instance-bound host authority must attest submitting ownership, image kind, readiness, immutable identity and retained accessible content. Byte validation/upload/transcode/auth stay in the host. A failed form must record no partial acceptance. Upload-success/submit-failure is separate: preserve the ready receipt and retry the same submission identity; accepted replay does not reauthorize or replace the original reference. Seeing an image grants read access through the actor projection, not submission ownership. Own unsubmitted uploads stay readable by their uploader; private typed references expose bytes to others only after their declared reveal. Discovery advertises the local PNG upload profile; the language image type is encoding-independent.

A real host must decide notification channels and participant preferences separately from activity audiences/triggers/deadlines. Authoring UI can populate host-supported choices. An explicitly required channel constrains compatibility; delayed in-app delivery cannot silently rewrite time-sensitive semantics. These remain open integration directions in the [existing research](../../research/app-integration-and-prompting.md), not new normative requirements invented by this review.

## Nonfunctional and authoring limits

- The envelope is bounded: 2–100 declared participants, at most 64 unique step IDs, 1–32 steps in each sequence, 16 settings, eight fields/form and 366 fixed recurrence windows. Pool quota is 1–8 items/actor. References are statically typed and scoped; there is no arbitrary code, arithmetic expression language or result-dependent branching. Relative duration bounds and safe integer-clock budget checks are explicit.
- Validation hosts are local HTTP/SQLite implementations with a shared serialization lock/transaction, a controlled test clock and approximately 20ms worker polling. Multi-process/distributed scaling, crash consistency under storage failures, quotas/expiry, load/latency targets, and real notification/rendering pipelines are not certified. Bounded package syntax is not a measured production performance guarantee; state/history/blob accumulation needs host policy.
- Local image uploads are at most 524,288 bytes, 1–1024 pixels/axis, 8-bit RGB/RGBA and noninterlaced. The corrected profile checks raw chunk names, CRCs, critical envelope/contiguous IDAT, bounded complete decompression and filter bytes. Other critical chunks are unsupported; ancillary metadata is opaque. It is not complete ancillary semantic validation, transcoding or general image-safety certification. All 29 adversarial/valid fixtures and authenticated image trials agree across hosts.
- The inspector renders a blueprint from JSON. It does not execute activities, choose instance settings, create assignments or provide a tested nontechnical authoring flow. Package data supports adjustability; ease of authoring/use still needs user-facing review. Package exchange does not transfer running state, identities or blobs.

## Recommended next decision

Decide whether **single non-self image-source assignment with an independently submitted text response** belongs in the initial core. If yes, the highest-value next bounded milestone is to preserve typed image identity and authorization through a closed source pool, saved assignment, actor-private readable projection and linked-result reveal, reusing the current named algorithms and exact retry/recovery rules. It need not add two alternatives, choice, fairness, audio/video, general concurrency or full Chorus parity. If excluded, name that exclusion plainly; image forms must not be described as image exchange.

Separately decide whether ongoing progress and permission-enforced feedback are required initial families or deferred capabilities. Then review the supported profile, authoring clarity, host embedding/prompt semantics and eventual version compatibility with the user. Prepare explicit exclusions and evidence rather than assuming a release from a count of passed examples. **Stop before any 1.0 identifier/release/readiness claim for the user's decision.** No runtime expansion occurs in this review.
