# Candidate 0.24 capabilities and limitations

Implemented: all retained 0.23 operations, plus top-level first-valid typed contribution acceptance with rolling two-person queue, qualified material/queue input, one immutable canonical entry, fresh shared windows, exact per-invitee replacement, previous-author exclusion, decline/withdrawal/reenrollment, bounded failed passes and safe-clock exhaustion. Text/image/audio kinds are package settings; the creative relay examples use text/image and a 24-hour window.

Demonstrated by independent Python/JavaScript engines and serial SQLite hosts: competing valid submissions, invalid owner/readiness attempts, deadline/ticket/predecessor rejection, canonical identity/closure, exact replay/restart, source grants, single successor consumption, failed setup rollback, creation retry, null-canonical backoff, odd-tail/exclusion, internal churn budget and unsupported/no-state behavior. A different composition continues into private pair reflection without interpreter changes. Exact compatibility compares all retained 0.23 traces.

Limits: package size/sequence/identity bounds remain retained. One relay invocation is bounded by one canonical acceptance or 100 failed transitions, at most 100 current and 256 lifetime bound identities. It does not include an indefinite run loop. Notification delivery, scheduler precision, durable transport, account infrastructure, media conversion/moderation, screens and product lifecycle need host integration. Canonical media grants require immutable true origin and authorized viewers. The demo denies genuinely new origin-unbound viewers; preauthorized origin viewers can join/rejoin. Source registries are local-host demonstrations, not a new cross-provider protocol.

Carry-over can keep an inactive person invited indefinitely when others contribute promptly. A losing person may lose repeatedly. Prior-author exclusion normally needs three available people. Odd eligible tails reuse one already attempted partner. A full failed pass stops with retry delay; clock exhaustion is non-resumable. The inspector remains pinned to 0.20 and the separate playground is unchanged.

Candidate evidence does not establish production notification UX, deployment or complete historical activity migration. Independent authoring/schema review cleared the completed implementation pin. Independent runtime clearance of the queue-audience correction remains unverified after a platform safeguard stopped the recheck; local validation does not substitute for it. See [verification and review limits](../../validation/0.24/EVIDENCE.md). Further development follows real-world use cases and demonstrated capability gaps.
