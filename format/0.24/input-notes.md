# Typed starting contributions and explicit fallback outcomes

Candidate 0.24 retains these versioned rules. [Generic typed pooling](pooling-notes.md) adds compatible new consumer versions without widening the old contracts.
Normative 0.22 additions. All 0.21 operation versions remain available with their exact historical semantics. New operations are top-level and use the same bounded phases, durable event ordering, host controls and typed media rules. No package launches another instance.

## Declared input contract

The envelope optionally includes `inputs`, an object with at most eight ordinary names. Each declaration is exactly `{type:"contribution",kinds:[...]}`, with a nonempty distinct subset of `text`, `image`, `audio`. Every declared input is required at setup, must be consumed by a binding reference, and requires `contribution_inputs@1`; non-text declared kinds also require their retained media capability. Unknown, missing, extra or malformed declarations/bindings reject. Old envelopes need not include `inputs`.

A qualified contribution is exactly `{ref:{instance,source,itemId},actor,value,round}`. `instance` is a canonical lowercase UUID URN (`urn:uuid:` followed by the usual hexadecimal UUID form), generated uniquely and durably bound by the host. `source` is the actual origin step ID, `itemId` the accepted nonempty scalar ID, `actor` the real origin author, `value` the exact immutable typed text/image/audio value, and `round` the originating round name or null for a retained unrounded pool. Input authors need not belong to the destination roster. None of these fields can be replaced by a copied label or a list index.

A normalized external binding is exactly `{candidate:<qualified contribution>,via:<handoff pointer>}`. The pointer is either `{instance,source,itemId,round}` for a direct origin contribution, or `{instance,result,round}` for the actual source selection that supplied the material. `via.instance` uses the handing-off instance's UUID URN. Its round identifies that contribution phase or selection's candidate-source round. For a direct contribution its identity/round must match the candidate origin; for a selection they may differ. Retaining old material never relabels its origin as a new contribution. This bounded provenance record is not a workflow graph.

This is one shared material definition for input bindings, frozen candidates, count rows, selected outcomes and presentations. `via` describes how that material was supplied, not a second contribution identity. Collection controls, effective actors, current-vote retries, closing and ballot/aggregate visibility use the retained contracts referenced below; authors do not reconstruct those rules with lower-level steps.

Hosts attest the entire normalized binding: exact origin identity, actual author/value/kind/round, accepted closed-source/final eligibility or settled selected outcome, the real handing-off pointer, full snapshot visibility for every destination viewer, and ready immutable origin-owned media/read authority. All destination viewers means the organizer, original roster, all supplied future-phase actors and every actor later added by host configure. Private metadata is protected along with bytes. Missing, false or exceptional attestation fails closed before target state/grants become visible. A package cannot attest its own inputs.

Initial bindings and instance identity are persisted atomically and remain immutable. Restore arguments cannot change them. Participant actions cannot bind inputs, inject origin/authority/time, or change instance identity. Before configure adds any viewer, the host must reauthorize access to every retained input snapshot and origin media; failure rejects the whole action without expanding bindings, projections or grants. Trusted durable restore retains prior attestation and never derives a fresh source value from a caller. Submission ownership stays at the origin; destination viewing grants do not confer media ownership.

## New typed instruction chain

- `artifact_pool@3`: exactly the fields of `artifact_pool@2`; `input` is null, `{binding:<declared name>}`, or `{result:<preceding select@2 ID>}`. No anonymous literal is added to this contract. A result must derive from the new typed pool/vote/tally chain. Collection/eligibility/deadline and one immutable contribution per actor otherwise follow `@2`. Save `input:{status,predecessorRound,candidate,via}`; `predecessorRound` equals `via.round` when a pointer exists and is null otherwise, and can differ from the material origin in `candidate.round`; null input has status `none` and null remaining fields, bound input status `initial`, result input preserves the preceding status. `via` is the bound pointer or `{instance:<current UUID>,result:<selection ID>,round:<selection's pool round>}`. Failed preceding results block collection with `blocked:true`; later steps still execute. Starting input is visible to every bound viewer at collection entry.
- `vote@2`: exactly `id,op,prompt,candidates,changes,ballots`; candidates is `{source:<preceding artifact_pool@3>}`. Every frozen candidate contains the qualified contribution shape above. Ballot payload is `{candidate:{instance,source,itemId}}`. Current-vote/retry/final-voter eligibility, source eligibility, exclusive closing and separate ballot privacy follow `vote@1`. Candidate values/authors/origins appear at voting entry, even before a configured future opening; all counted votes do not automatically close the phase. Existing predefined-option polls continue using unchanged `vote@1`.
- `tally@3`: `id,op,source` referencing a preceding `vote@2`; retains `tally@2` counts/totalVotes with qualified candidate snapshots, privately computed.
- `select@2`: `id,op,source,policy,ties`, plus optional `noVotes`. Source is a preceding `tally@3`; policy is `policy:most_votes@1`; ties is unresolved or random, with existing random-tie policy requirement. `noVotes` defaults to `unresolved`; allowed opt-ins are `random` (`policy:random_candidate@1`) and `retain_input` (`policy:retain_input@1`). Retention is statically valid only when the underlying pool's input is a binding or a preceding selected-result reference. Null starting input is invalid for retention. Output retains counts/totalVotes/status/selected/tied and adds nullable `basis` according to the matrix below.
- `present@2`: the fields/visibility of `present@1`, with source restricted to preceding `tally@3` or `select@2`. Permanently presents the structured result without disclosing individual ballots. Render `basis` honestly: a retained/random no-vote fallback is not a voted winner.
- `reveal_ballots@2`: `id,op,source` naming a preceding `vote@2`, explicitly publishes its current ballots and voter identities. Omission retains their privacy after aggregates appear.

All qualified candidate reference fields must exactly match the frozen candidate. Wrong origin instance, round/step confusion, stale execution keys or copied values reject. A contribution in a later collection receives that destination instance/step/item identity and round; the starting source retains its original identity. A named input is reusable by multiple declared steps without rebinding it.

## Exact outcome matrix

| Condition | status | selected | tied | basis |
| --- | --- | --- | --- | --- |
| Zero candidates, any noVotes setting | no_candidates | null | empty | null |
| Candidates, zero votes, omitted/unresolved | no_votes | null | empty | null |
| Candidates, zero votes, random | selected | one frozen eligible candidate | empty | random_no_votes |
| Candidates, zero votes, retain_input | selected | actual usable starting candidate | empty | retained_input |
| Positive votes, unique maximum | selected | highest candidate | empty | most_votes |
| Positive votes, unresolved highest tie | tie | null | highest candidates | null |
| Positive votes, random highest tie | selected | one highest candidate | highest candidates | random_tie |

No-vote outputs retain every original zero count and totalVotes zero. A retained source need not be a candidate and receives no invented vote row/count. Zero candidates always takes priority: retention is deliberately a response to proposed continuations without a voting decision, not a general fallback for absence of participation/material. A host may externally choose how to respond to an empty activity but cannot claim that the package selected anything. Failed predecessor input closes its dependent collection empty, so retention cannot create usable material from that failure.

Random no-vote choice has equal chances among all frozen eligible candidates; positive ties have equal chances among tied highest candidates. No generator or cross-host sequence is prescribed. A one-member choice needs no random draw. Resolve once and persist the entire result atomically; retries, reads, workers and restart do not reroll. Empty/default/retention outcomes consume no draw. Trusted injected draws can test membership and durability without exposing random machinery to participants or package authors.

## Reference host binding profile

Privileged instance creation accepts `hostBindings` mapping each declared name to exactly `{instance:<local source ID>,source,itemId}` or `{instance:<local source ID>,result}`. These are host API lookup requests, not normalized package input values. The host resolves actual stored source data and globally qualified identities. Accepted contribution sources must be closed, finally eligible and fully projected to every destination viewer; selection sources must be settled selected outcomes and explicitly group-presented. The organizer has no private-content bypass. Wrong pointer/type, private/unready material, altered supplied fields and unsupported input capability reject before creating the destination instance or grants.

The local host stores origin-media read grants without copying/reassigning ownership, verifies origin instance/author/kind/readiness, and serves bytes only when the destination viewer can see the bound material in their projection. New actor controls must satisfy the same full-snapshot origin access check. UUID identities survive local names, retries and restart. Origin records/blobs must remain durably available; deletion, cross-provider trust/transfer, grant administration, distributed ordering and production failure robustness remain host responsibilities outside this demonstration.

Hosts can attest other legitimate source registries using the same language guarantees. The package does not contain a host-specific storage location or successor schedule. Result-derived eligibility, designated-person tie timeout/fallback, calendars, unlimited streams, multiple typed contributions, video and complete product migration remain deferred.
