# Candidate 0.22 supported profile for review

The demonstrated core is collect → vote → select → present, with a declared actual starting contribution and a generic host boundary for carrying selected material into a separate instance. Finite linked rounds inside an instance remain available. Earlier text item loops and source/response instructions already demonstrated ordinary saved-material reuse; this profile adds selected typed origin/authority rather than claiming all reuse is new.

Four new witnesses supplement thirty retained examples: a closed group-visible starting contribution; text/image/audio creative continuation with random no-vote fallback; deliberate source retention when candidates exist but counted votes do not; and a supplied-brief proposal selection, shared planning and private pair exercise. Definitions transfer through identical bytes/digests and use generic operation dispatch.

## Demonstrated guarantees

- Stable UUID-qualified material identity with real author/value/round; separate direct-contribution or selection handoff provenance. Retention can pass old material through a newer decision without relabeling it.
- Required typed declarations and fail-closed whole-snapshot attestation. Setup covers organizer/roster/future actors; later additions require access to every supplied origin snapshot before state/grants expand. Private/unready/wrong/withdrawn sources reject without target creation.
- One current qualified ballot, configurable replacement, exact retry semantics, exclusive closing and private individual ballots after aggregate/outcome presentation. Candidates publish at voting entry; receiving all votes does not close voting.
- Exact unique/tie/default/no-vote/no-candidate result states with explicit basis; opt-in equal-chance random no-vote choices and source retention. Zero candidates remains empty under every new policy. Durable outcomes survive reads/workers/retry/restart.
- Actual origin-owned PNG/WAV reads across three instances and authorized new-viewer expansion without granting submission ownership; foreign media submissions reject. Multi-input failed expansion creates no new grants.
- Exact retained state/results/views, independent interpreters, durable authenticated SQLite hosts and materially different supplied-brief/pair composition. See [evidence](../../validation/0.22/EVIDENCE.md).

## Host boundary and remaining limits

The host authenticates/enrolls actors, chooses dates/timezones and successor launch timing, generates unique instance identities, attests authoritative origins/eligibility/access, retains durable records/media and renders typed results. The reference profile resolves sources inside one host's SQLite store and retains origin read grants. Cross-provider trust/transfer, origin deletion/retention, grant administration, media processing/rendering, notifications/attention, accounts and interface design remain host engineering.

At most eight input declarations; all required/used. New operations remain top-level; retained 32-step sequences, 64 step IDs and 256 bound identities remain bounded. Old native package envelopes require explicit host support; no live-state migration or running-instance exchange is supplied. Source registries may be different in a production host if they attest the same language guarantees.

Deferred: designated-person tie timeout/fallback, result-derived previous-winner eligibility, video, multiple typed contributions per actor, exposure/offer policies, unassigned responses, unlimited streams, thread-ending/restart rules, arbitrary templates/expressions and universal calendar/role administration. Voting sources remain the specified typed pools; arbitrary forms/response records have no implicit candidate adapter. Empty collection still stops even under retention.

Private ballots are access control, not universal anonymity. Public attribution, small-group counts and external information can reveal choices. The local serial SQLite trials do not establish distributed ordering, load/performance, arbitrary storage-failure robustness or production integration. PNG/WAV are reference host upload profiles, not language encoding restrictions. Thirty-four examples and useful creative support do not imply faithful product migration: six complete historical translations remain six, fourteen incomplete. Independent review and user decisions precede any merge/publication or later release.

[Typed pooling assessment](POOLING-ASSESSMENT.md) records the authorized direction for 0.23: accepted kinds and per-person quotas are independent author settings, with compatible typed iteration/source consumers. No such quota or iteration changes are included in 0.22.
