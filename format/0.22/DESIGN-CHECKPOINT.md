# Candidate 0.22 design checkpoint

October 1, 2026. Base: clean main `ff0581e`, including the user's repository cleanup. Next incremental candidate after 0.21. This checkpoint precedes implementation and validation; it is not a release or production support claim.

## Proposed bounded contract

Authors can say: continue this supplied contribution, collect possible continuations, vote privately, select an outcome under explicit policies, and show the result. The host can then start a separate instance and supply the real selected contribution through the same generic input declaration. Starting another instance, dates, accounts and media infrastructure remain host duties.

## Exact decisions for implementation

- At most eight input declarations, each with a name and nonempty distinct subset of text/image/audio kinds. Declaration kinds require the corresponding retained media capabilities. Declared inputs are required, with no anonymous executable template, lookup path or optional default. A declaration must be used by a binding reference. No declaration is added to old packages.
- `artifact_pool@3` has the same collection fields as `@2`, but input is only null, `{binding:name}`, or `{result:<preceding select@2>}`. A result must derive from the new typed pool/vote/tally chain. All new operations remain top-level. Finite within-instance rounds remain supported; no loop or stream system is introduced.
- `vote@2` uses a preceding `artifact_pool@3` source. Existing predefined-option voting stays available through unchanged `vote@1`; a second literal-option syntax is unnecessary. New ballot payloads carry the complete qualified reference. Current-vote, eligibility, closing, retry and privacy rules otherwise retain 0.21's observable guarantees.
- `select@2` retains counts, totalVotes, status, selected and tied, and adds nullable `basis`: `most_votes`, `random_tie`, `random_no_votes` or `retained_input`. A retained input need not belong to the candidate pool; it is explicitly a starting-source fallback and is not assigned a fabricated vote count. The underlying starting source must be a binding or selected-result reference, not null. An unresolved referenced input still blocks collection, so the fallback cannot create usable material from a failed predecessor.
- `noVotes:retain_input` is statically valid only for a selection derived from a pool with a binding or result input. Zero candidates always takes priority over no-vote fallback. Random no-vote selection includes every frozen eligible candidate with equal chances, and occurs once; a unique candidate may be selected without a random draw. Positive-vote ties still use the separately declared existing tie policy.
- A normalized external binding is `{candidate:<qualified snapshot>,via:<handoff pointer>}`, not a copied label/value claimed by the caller. `via` is `{instance,source,itemId,round}` for a direct contribution or `{instance,result,round}` for a selection; it records the actual handing-off decision separately from immutable material origin. Instance identities are canonical globally unique UUID URNs, generated and durably bound by the host. Engines require an explicit trusted attestation callback and stable instance identity for the new contract. Persisted binding data cannot be replaced by retries, participant actions, restore arguments or actor changes lacking source authorization.
- The reference HTTP host's privileged setup accepts only an origin pointer (`{instance,source,itemId}` or `{instance,result}`), resolves actual closed/publicly projected contributions or settled/publicly presented selections from durable state, verifies every target actor's source access and ready owned media, and saves the normalized snapshot and durable read grants. Private source material without a projection is rejected even for the organizer. This bounded same-host authority profile does not define cross-provider trust, grant administration or copying ownership.
- Hosts may support additional legitimate source registries/transfer protocols by attesting the same language-level input guarantees. The package cannot supply its own authority proof or automatically launch another instance. The language makes no universal anonymity, calendar, notification, faithful product migration or production certification claim.
