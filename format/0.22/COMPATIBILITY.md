# Candidate 0.22 compatibility and migration

Base: clean main `5677de6`, including the user's neutral-name cleanup. Candidate numbering follows the repository's incremental format directories. This is a local pre-1 candidate prepared for independent review.

- **Format:** `harmonomicon.activity-package/0.22` negotiates exactly. Supporting it does not implicitly support a 0.21 envelope. A host verifies every required operation, policy and capability before creating target state or input grants.
- **Package revision:** `(id,version)` and canonical digest remain immutable. The thirty retained examples receive patch revisions for their changed envelope; four new examples have distinct IDs. The draft creative package's authoring status was revised from `0.1.0` to `0.1.1` before final validation. Library versions are a separate file-history mechanism.
- **Operation versions:** every retained version keeps its source restrictions, output shapes, counting/privacy/deadline/retry behavior and random contract. New behavior uses `artifact_pool@3`, `vote@2`, `tally@3`, `select@2`, `present@2`, `reveal_ballots@2`, `contribution_inputs@1`, `policy:random_candidate@1` and `policy:retain_input@1`. Existing predefined polls remain on `vote@1`.
- **State:** only the new contract adds UUID instance identity and immutable normalized input bindings to engine state. An old-operation package translated by changing its envelope retains exactly the historical state/results/views. This demonstrates operation compatibility, not implicit native-envelope negotiation or live-state migration.
- **References:** new typed ballots carry instance/source/item identity; new result and pool references are preceding and top-level. Old loops, assignments and votes accept their original source types. No automatic bridge from arbitrary forms, response collections or predefined labels to typed material is claimed.
- **Host exchange:** activity definitions transfer with identical bytes/digests. The input contract supports separately launched instances and authoritative source snapshots. The reference host resolves origins in its own durable store; cross-provider trust, blobs and running-state transfer are not supplied by package exchange.
- **Authority:** restore and retries keep the attested snapshot. Explicit replacement UUID/binding arguments reject. A later actor must be authorized for every supplied snapshot before bindings/projections/grants expand; the organizer has no private-source bypass.
- **Empty/default outcomes:** unchanged old `select@1` and omitted `select@2.noVotes` retain the no-vote stop. Random/retention are opt-ins. All no-vote settings preserve `no_candidates` for an empty eligible pool; no draw or retained selection is invented.
- **Historical preservation:** prior format/validation directories are untouched. Hosts must retain an old engine for existing instances or separately design and validate migration. No automatic storage/instance upgrade, release or 1.0 decision is supplied.

The conformance checker compares all 57 prior traces against both actual historical 0.21 interpreters in separate processes, with exact complete state/results/views. Both new durable implementations run the retained host suites and consequential input/policy boundaries. Random sequences are not compared between unseeded hosts; injected choices and durable properties validate the promised rule.

Six exact legacy migrations remain complete and fourteen incomplete. Typed source handoffs and a useful creative core do not count as faithful product migration. See [checklist](MIGRATION.md), [supported limits](readiness-assessment.md) and [evidence](../../validation/0.22/EVIDENCE.md).
