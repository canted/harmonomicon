# Candidate 0.20 supported profile for pre-1 review

This candidate follows the authorized narrowed boundary: essential activity house rules in a composable language, with host-owned roles, dates, discussion and media infrastructure. In-app composition remains primary; cross-app portability is secondary and demand uncertain. This is not a 1.0 readiness declaration.

## Demonstrated core

Structured check-ins/decisions, fixed recurring practice, turn-based stories/guessing, text pools/claims, group deliberation, non-self source-response exchange, scoring and image forms remain supported. Typed image sources now flow through saved assignment to independent text/audio responses and linked reveal. New host-controlled primary collection supports public Feedback pieces and a private solo journal. An authored typed exchange then private-pair reflection demonstrates reuse across operation families; no activity-name dispatch was added.

Evidence: 26 schema-valid examples, 44 normative engine traces, 129 invalid definitions, prior 38-trace compatibility, serialized restart at every event boundary, two actual durable hosts, authenticated image/audio bytes/grants, races, retries, worker-only completion, immutable export/import and private continuation. Prior six complete legacy migrations remain six; fourteen historical migrations remain incomplete. The pinned 0.19 constructed challenge remains historical evidence, not an estimate of all activity coverage.

## Essential invariants and host obligations

Stable accepted contribution/assignment identity; explicit self-exclusion and source eligibility; declared visibility and typed read grants; independent response progress; exact retries/replay and durable serialized effects; exclusive deadlines; no silent replacement of time-sensitive semantics by late delivery. Hosts must authenticate and bind identities, resolve dates/timezones, authorize immutable ready owned media, retain blobs, serialize/persist events and progress deadlines. Application roles select effective actors; organizer identity does not grant private access. Clients cannot claim authority/time/configuration.

Notifications, participant preferences and what starts a time-sensitive prompt deadline remain open integration choices in the existing research, not universal channels invented by this candidate. UI may offer host-supported capabilities. Explicit required channels constrain compatibility. Authoring usability and clear unsupported-choice presentation need user-facing review.

## Remaining essential review versus optional scope

**Next review work:** independently inspect the 0.20 contract and implementation, especially effective-actor/date changes, media grants, timing and identity recovery; assess authoring clarity for the three witnesses and a held-out combination. Decide the supported initial profile and exclusions with the user. Version compatibility/release policy and production host requirements are separate decisions. Do not automatically add another primitive or promote to 1.0.

**Unsupported unless deliberately chosen later:** permission/result-dependent gates, open activity streams whose outputs feed later steps, replacements/moderation, nested typed pools/responses, audio in ordinary form fields, video, general concurrency/branching, dynamic language-level calendar recurrence, running-instance transfer and result-driven scheduling. Generic open host discussion does not require an activity stream primitive when later operations do not consume it. Host daily instances are not a language recurrence feature.

**Optional faithful product refinements:** two-cover offers/choice, exposure fairness, late-third-cover handling, exact Chorus or Feedback product replication and every historical migration. None is an automatic pre-1 prerequisite. Uploads/transcoding/drafts/publication/chat/role administration stay outside the language unless an explicit activity dependency requires an input/operation.

**Nonfunctional limits:** bounded runbooks and static references, no arbitrary code; up to 100 effective actors/phase and 256 bound identities; one immutable entry/actor in each new phase. Local SQLite reference hosts are serialized single-process validation profiles, not distributed/performance/load/storage-failure certification. State/history/blob retention needs host policy. PNG and WAV are small advertised reference profiles, not comprehensive media/rendering safety certification. The inspector is a structural blueprint, not an execution or usability certification.

Stop before any 1.0 label/release/readiness claim for the user's explicit review. No merge, push or deployment is part of this milestone.
