# Migration checklist for the twenty 0.12 examples

This checklist measures complete migration of each earlier package, including its timing, setup choices, acceptance rules, missing-contribution behavior, and audience views. It does not count a similarly named activity with different rules as a completed migration. Candidate 0.14 has ten example packages, but they are not replacements for all twenty earlier examples.

**Current result:** zero complete migrations; twenty need additional operations or parameter bindings; none is classified as intentionally outside the 1.0 goal. The earlier packages remain usable under candidate 0.12. The six 0.13 examples are carried into 0.14 with new package revisions and passing unchanged conformance traces. The four additional examples test pools, claims, group assignment and combinations of them.

The [machine-readable checklist](migration.json) has one entry for every 0.12 example. The checker verifies that this set matches the earlier examples, contains no duplicate rows, and names a concrete gap for every incomplete migration. A future candidate may move a row to `expressible` only with a runnable translated package and comparison traces that cover the listed rules. `outside_scope` requires an explicit documented scope decision; no current row uses it.

The first shared gap to address is generic collection timing and instance parameter binding. That work can recover the exact check-in and support the repeated-prompt families without inventing a separate activity contract. The partition examples already recover useful digital coordination, while their public progress metadata and prebound setup options still differ from 0.12. Those differences remain named in this checklist.

Subsequent work needs concealed handoff, reusable multi-source offer policies, media, scoring, permission gates, and ongoing streams. Completion counts and delayed reveal must be chosen by package data rather than inferred from a prompt. The [roadmap](../../ROADMAP.md) uses this checklist alongside the [strict activity challenge](../../experiments/format-0.12-coverage-challenge/README.md) to choose and validate later candidates.
