# Candidate 0.23 compatibility and migration

Base: completed reviewed 0.22 at `5006b99cb850d51ba82991e5740cfdf60a7f32d2`, whose implementation was independently reviewed at `88ce95c`. Candidate 0.23 is isolated on `codex/candidate-0-23`. Main and all historical candidate files remain unchanged.

- **Envelope and capabilities:** `harmonomicon.activity-package/0.23` negotiates exactly; native older envelopes require explicit host support. Every declared operation/policy/capability is checked before instance state or grants exist.
- **Immutable package identity:** the 34 retained examples receive patch revisions for the new envelope. Six original examples have distinct IDs at `0.1.0`. Equal `(id,version)` means equal canonical bytes/digest. Definition exchange does not exchange live state or media.
- **New behavior:** `pool@2` separates `kinds` and `perActor`. `for_items@2`, `assign_item@2`, `acknowledge@2`, `reveal_item@2` supply attributed typed iteration. `vote@3`, `tally@4`, `select@3`, `present@3`, `reveal_ballots@3` extend the qualified chain to compatible typed pools. `assign_artifacts@2`, `artifact_response@2`, `reveal_artifact_responses@2` extend one-source exchange. The deterministic multi-item rule is a new `policy:next_nonself_item@1`; old single-entry policy semantics stay exact.
- **Old contracts:** old untyped `pool@1`, anonymous text iteration, single-entry typed pools, predefined polls, qualified input/voting versions, source restrictions, results, private views, closing, retries and randomness remain unchanged. New consumers accept `artifact_pool@1/@2/@3` and `pool@2`; old consumers do not silently widen. An input needing an actual qualified snapshot cannot consume an anonymous old literal.
- **New state:** new pooling instructions use qualified instance identity and private typed-item snapshots. With only retained operations, changing the envelope/package revision preserves exact historical outcomes, complete state and every actor view. This is tested against all 73 actual historical 0.22 traces in both interpreters, not just fixture expectations.
- **Privacy:** item-loop sharing is attributed and explicit. It does not promise old anonymous text disclosure. Multiple private contributions are author-visible; assigned readers receive only their actual material; unused source items stay private after linked response reveal. A reference string grants neither reads nor submission ownership.
- **Timing:** filling quotas does not close a pool; closing remains host-controlled. Inclusive opening/exclusive closing, retained accepted-event replay and ordered atomic acceptance remain. Conservative resolved-date budgets include up to 800 eligible typed iterations; null closing retains capped late-deadline behavior.
- **Authority and host inputs:** whole-snapshot/all-viewer authorization, immutable origin and separate `via` provenance remain mandatory. A new pool or selection can supply a declared qualified input. Later viewer expansion must authorize every binding before any state/grant change. Cross-provider trust or running-state migration is not supplied.

The engine/schema suite checks 108 traces, 324 invalid definitions and 40 examples. Both durable hosts run retained suites and new real-byte pooling/consumer trials. Random outcome policies validate eligible membership and durable selection; equivalent hosts need not generate the same random sequence. Retained seeded assignment keeps its existing reproducible contract and samples eligible items in accepted order.

Six historical migrations remain complete and fourteen incomplete. Generic typed pooling and simpler creative/exchange activities do not implement balanced two-offer choice, response-record voting adapters or broader product lifecycle. See [migration](MIGRATION.md), [profile](readiness-assessment.md), [decision record](DECISIONS.md) and [evidence](../../validation/0.23/EVIDENCE.md). No automatic instance upgrade, merge, release or 1.0 decision occurs.
